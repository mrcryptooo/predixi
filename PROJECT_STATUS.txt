1. ONE-PARAGRAPH PROJECT SUMMARY
--------------------------------------------------------------------------------
PrediXI is a Web3 football prediction platform built for the Base App ecosystem
(Coinbase's blockchain). Users connect a crypto wallet, predict football match
outcomes (Home Win / Draw / Away Win), earn XP points and badges for correct
predictions, and compete on a global leaderboard. The app is a Standard Web App
(not a Farcaster Mini App), built with Next.js 16, TypeScript, Tailwind CSS,
Wagmi for wallet connection, and Supabase as the database. Match data, leaderboard,
and user profiles are currently all demo/mock data. The real Supabase backend
exists and works for saving predictions, but pages still display hardcoded data.

7. MISSING ENVIRONMENT VARIABLES
--------------------------------------------------------------------------------
These 3 variables MUST be set in .env.local (local dev) and Vercel (production):

  NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
  (Find in: supabase.com → Project → Settings → API → Project URL)

  NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJ...
  (Find in: supabase.com → Project → Settings → API → anon public)

  SUPABASE_SERVICE_ROLE_KEY=eyJ...
  (Find in: supabase.com → Project → Settings → API → service_role secret)
  *** NEVER SHARE THIS KEY — gives full database access ***

Optional:
  NEXT_PUBLIC_BASE_BUILDER_CODE=your_builder_code
  (Find in: base.dev → Settings → Builder Code)


8. URGENT WARNING
--------------------------------------------------------------------------------
⚠️  SECURITY RISK — DO NOT LAUNCH WITH REAL USERS YET

The file src/app/api/predictions/route.ts accepts POST requests that claim to
be from any wallet address WITHOUT VERIFYING the request actually comes from
that wallet's owner.

Ethereum wallet addresses are PUBLIC. Anyone can find a wallet address and
submit fake predictions on that person's behalf.

BEFORE real users use this app, you MUST add wallet signature verification:
  1. Frontend: wallet signs a message containing the prediction details
  2. Backend: server verifies the signature matches the claimed address

This is called EIP-191 message signing and is standard practice.
Ask ChatGPT or Claude to implement this before launch.

⚠️  Also check that your SUPABASE_SERVICE_ROLE_KEY is NOT visible anywhere in
    your git commit history. If it was ever accidentally committed, go to
    supabase.com → Settings → API → and regenerate the key immediately.
